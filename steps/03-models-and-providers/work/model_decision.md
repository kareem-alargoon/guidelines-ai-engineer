## 3. نتايج الـ eval (Task 6)
15 إيصال وهمي (عربي، وإنجليزي، ومخلوط، وفيهم فخاخ)، و `temperature=0`، و JSON schema:

| الموديل | total | date | vendor | currency | كل الحقول | ث/إيصال | Memory | License |
|---|---:|---:|---:|---:|---:|---:|---:|---|
| `qwen2.5:3b` | **100%** | **100%** | 80% | 93.3% | 73.3% | **2.85** | 2.16 GB (CPU) | ❌ `qwen-research` |

- **عدّى أرقام الـ threshold** (≥ 95% في الـ total والـ date، و < 30 ث)، **بس الـ license بيوقّعه.** فمفيش موديل عدّى كل الشروط لحد دلوقتي.
- الغلطات كلها **نسخ من غير تصليح** (OCR noise في اسم المورّد، و `SR` بدل `SAR`). وده ممكن يتحل بـ prompt أحسن أو post-processing، أو بموديل أكبر.
- ⚠️ 15 إيصال وهمي = regression test، **مش دليل**. بالـ rule of three، 15/15 معناها إن الدقة غالباً > 80% بس. ولسه محتاجين الـ **50 إيصال الحقيقيين** (`use_case.md`).
- ⚠️ الـ eval كان على **نص** طالع من OCR، مش على صورة. يعني فيه خطوة OCR (أو موديل vision) قبله ولسه ماتقاستش.

## 4. التكلفة (Task 7، `python cost.py`)
80 إيصال في اليوم × 22 يوم شغل = **1,760 إيصال في الشهر**. ومتوسط 330.5 input و 49.8 output token (من Task 6). وأسعار Anthropic snapshot يوم **2026-11-13**:

| Model | $/إيصال | عادي | batch | cache | batch+cache |
|---|---:|---:|---:|---:|---:|
| Haiku 5.5 | 0.000058 | **$0.10** | $0.05 | $0.08 | $0.04 |
| Sonnet 5.5 | 0.0012 | $2.04 | $1.02 | $1.49 | $0.74 |
| Opus 5.5 | 0.0023 | $4.08 | $2.04 | $2.97 | $1.49 |
| Fable 5.2 | 0.0046 | $8.16 | $4.08 | $5.89 | $2.95 |
| Local `qwen2.5:3b` | $0 | $0 | | | |

- **الـ API رخيص جداً على الحجم ده.** حتى Fable = $8 في الشهر، و Haiku = 10 سنت. يعني **التكلفة مش هي اللي بتحسم.**
- **الـ local "مجاني" بس مش ببلاش:** الجهاز، والكهربا، والتحديثات، وحد يصونه. والجهاز بيخلّص الـ 80 إيصال في **~4 دقايق compute في اليوم**.
- ⚠️ **تقدير مش فاتورة:** الـ tokens دي بـ tokenizer الـ Qwen، وموديلات Claude الجديدة بتطلّع ~30% tokens أكتر (جزء 3.2). وعمود الـ cache بيفترض إن الـ system prompt (~172 token) هيتعمله cache، وده **ممكن مايحصلش** لأن الـ prompt caching ليه حد أدنى للطول (هنتأكد منه في Step 04).

## 5. القرار
**Local، بشرط إن موديل Apache 2.0 يعدّي الـ eval. والـ API مرفوض حالياً، بسبب الـ privacy مش التكلفة.**

- **ليه local؟** الـ privacy (hard attribute) بيمنع إرسال إيصالات حقيقية لـ API برّه. والـ latency مش مشكلة (job في الخلفية، و 2.85 ث أقل بكتير من الـ 30). والـ hardware كفاية.
- **ليه مش `qwen2.5:3b`؟** الـ license. ولو اشتغلنا بيه في منتج تجاري، دي مخاطرة قانونية، حتى لو الدقة كويسة.
- **الخطوة الجاية:** نشغّل نفس الـ eval على **`qwen2.5:7b`** (Apache 2.0، ~4.7 GB): المتوقع دقة أحسن في الـ vendor والـ currency، بس أبطأ على الـ CPU بحوالي 2–2.5 مرة (`hardware.md`)، يعني ~6–7 ث للإيصال، ولسه تحت الـ 30 ث بكتير. **وده توقّع، لازم نقيس**. ولو بطيء أوي، نجرّب `qwen2.5:1.5b`. وبعدها الـ 50 إيصال الحقيقيين.
- **الـ API كـ أداة تطوير بس:** Claude (Haiku أو Sonnet) **بإيصالات وهمية** عشان نعمل داتا للـ eval، أو نقارن بيه الموديل الـ local (baseline لأعلى دقة ممكنة).
- **هجين (executor/advisor) مش دلوقتي:** فكرة إن الـ local يعمل الشغل، والإيصالات الصعبة تروح لموديل أقوى، كويسة. بس الموديل الأقوى ده لازم يبقى local هو كمان، أو API بعد موافقة قانونية.

## 6. إيه اللي يخليني أغيّر القرار
- **موافقة قانونية على الـ cloud** (مثلاً provider عنده data residency أو عقد DPA، و Anthropic بتزوّد 10% على الـ US-only inference): ساعتها Haiku 5.5 + Batch يبقى أسهل وأرخص من صيانة سيرفر.
- **مفيش موديل Apache 2.0 يعدّي الـ eval:** ساعتها يا GPU (موديل أكبر)، يا license تجاري من Alibaba، يا API بعد إخفاء البيانات.
- **الحجم يكبر 100 مرة** (8,000 إيصال في اليوم): الـ local على الـ CPU = 8,000 × 2.85 ث ≈ **6.3 ساعة compute في اليوم** على جهاز واحد، فهنحتاج GPU أو أكتر من جهاز. والـ API = Haiku ~$10 في الشهر، و Fable ~$816. (كلام الكتاب: نعيد الحساب في كل مرحلة scale.)
- **موديل جديد** (local أصغر وأقوى، أو license أوسع) أو **leaderboard جديد** يقيس العربي.
- **Deprecation:** موديلات الـ API بتتشال في مواعيد (صفحة Anthropic Deprecations)، فلو روحنا API محتاجين eval جاهز نعيده على الموديل الجديد. والـ local مابيتشالش، بس مابيتحدّثش لوحده.
- **الدقة على الإيصالات الحقيقية** (خط إيد، وصور وحشة) تطلع أقل من الـ threshold.
